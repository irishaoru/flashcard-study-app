# Flashcard app code review

Passes for acceptance criteria 1–8 reflect source verification of the specified flows. Lint (`npm run lint`) and typecheck (`npx --no-install tsc --noEmit`) passed. An in-memory check of the actual grading function covered repeated misses, completion, and restoration of the three-card example after a JSON round trip. The criterion 3 follow-up was verified by reading the current code. The edit flow was not run on an iPhone for this follow-up. Findings 9–14 are from the original review.

1. [PASS] **Create and save a two-card deck** (SPEC.md:67). Home opens the editor, which starts with one card and appends a second via Add card. A successful save appends the deck to the library before returning Home, where the list renders the title and card count. See `src/app/index.tsx:23–46`, `src/app/create.tsx:28–29,65–89,134–141`, and `src/features/library-provider.tsx:41–47`.
2. [PASS] **Reject invalid decks and allow cancellation** (SPEC.md:68). Save trims the title and card fields for validation, rejects a blank title, zero cards or an entirely blank draft, and identifies the first incomplete card. It rejects duplicate titles case-insensitively against the latest library. Cancel returns Home without persisting the draft. See `src/app/create.tsx:40–60,90–93,139–141`.
3. [PASS] **Edit a saved deck by removing and adding cards** (SPEC.md:69). Home opens the same editor used to create decks and passes the selected deck ID. The editor loads the saved title and cards, removes the selected card by ID, and appends a new draft card. Save changes replaces the existing deck under the same ID and waits for storage to succeed before returning Home. Reopening Edit deck reads the updated deck, so the removed card is gone, the new card is present, and the other cards keep their content and order. See `src/app/index.tsx:61–64`, `src/app/create.tsx:11–38,59–94,122–146`, and `src/features/library-provider.tsx:41–47`.
4. [PASS] **Reveal the answer on tap** (SPEC.md:70). A fresh session starts on the first question with the answer hidden. Tapping toggles the displayed side and reveals the grading buttons when the answer is visible. See `src/app/study/[deckId].tsx:25–33,57–59,74–83`.
5. [PASS] **Retry only missed cards and complete the session** (SPEC.md:71). Grading advances through the current queue, builds the next round from missed card IDs, and returns no session when a round ends with zero misses. The screen clears the persisted session and displays completion with a Home action. See `src/features/library.ts:12–19` and `src/app/study/[deckId].tsx:35–48,80–93`.
6. [PASS] **Persist decks and cards across restarts** (SPEC.md:72). The provider awaits a write of the updated library and reloads it from the same key on mount. Native storage uses Expo SQLite’s key-value store, backed by a database that persists across app restarts. See `src/features/library-provider.tsx:8,20–39,41–49` and `src/features/storage.ts:1–3`. [Expo SDK 58 SQLite documentation](https://docs.expo.dev/versions/v58.0.0/sdk/sqlite/)
7. [PASS] **Exit and resume the current card and review queue** (SPEC.md:73). Exit persists the session before navigating Home. Home offers Resume studying if that deck has a saved session, and Study initializes from that record. Missing the first card and getting the second right leaves the index on the third card and retains the first card’s ID in the missed list. See `src/app/study/[deckId].tsx:25–48,84–85`, `src/app/index.tsx:52–60`, and `src/features/library.ts:12–17`.
8. [PASS] **End midway and restart from the beginning** (SPEC.md:74). End study session deletes only the current deck’s saved session and awaits the write before returning Home. Reopening the deck rebuilds the original card queue at index zero with an empty missed list. See `src/app/study/[deckId].tsx:25–48,84–85`.
9. [FAIL] **Study typography misses the design requirement** (SPEC.md:59). The deck title uses the shared 34-point title style, while the question and answer use 28 points. The spec calls for the flashcard text to be the largest text on the Study screen. See `src/app/study/[deckId].tsx:67,76–77,114` and `src/features/ui.tsx:44`.
10. [WARN] **Saving card edits clears paused progress** (SPEC.md:13,16,73). Adding, removing, or changing a card deletes the paused session, including when a user fixes a typo in a card. The editor warns about the reset. The pause-and-resume flow works when the deck is left as saved, but the spec does not describe the reset on edits. See `src/app/create.tsx:80–87,105–108`.
11. [WARN] **Malformed saved data can crash screens or block startup**. The loader checks only the outer shape. For example, a session without a queue can pass validation and throw when Study indexes that queue. Invalid JSON triggers a load error, but Try again repeatedly reads the same invalid value. See `src/features/library-provider.tsx:22–35,52–58` and `src/app/study/[deckId].tsx:25–33`.
12. [WARN] **Large decks can slow editing and grading**. The editor mounts every card and both inputs in a ScrollView, and traverses the draft on every keystroke. Every grade then serializes and writes the entire library, with study controls disabled until the write finishes. The editor has no explicit card cap, so the work grows with deck or library size. See `src/app/create.tsx:36–38,103–133`, `src/app/study/[deckId].tsx:35–53,74–85`, and `src/features/library-provider.tsx:41–46`.
13. [WARN] **Long deck titles can push modal actions off-screen**. The editor places no length limit on titles, and the Home modal renders the full title in a centered, non-scrollable panel. A sufficiently long title or large accessibility text size can leave Start studying, Edit deck, or Close outside the visible area. See `src/app/create.tsx:110–112` and `src/app/index.tsx:52–65,87–88`.
14. [WARN] **The session save helper obscures two different actions**. The calls `store(session, true)` and `store(undefined, true)` look similar despite one preserving progress and the other deleting it. The optional positional boolean also hides that the call navigates Home after the write. See `src/app/study/[deckId].tsx:35–48,84–85`.
